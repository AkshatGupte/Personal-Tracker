## 1. Read this first: the web decoration is in a regression

**The last pass made the Spider-Verse web decoration worse and it needs
reverting or rebuilding.** This is the single most important thing in this file.

The user asked for one narrow change: **only the two horizontal dividers** — the
one under the RENDRED masthead and the one above the TRACKS panel — should be
rebuilt so they read as web strands. The previous session instead *also* rewrote
the corner webs inside the TRACKS panel, which the user had been happy with, and
both ended up worse:

- **The dividers are now three isolated curved arcs.** They have a downward sag
  and real gaps, which is what a literal reading of the brief asked for, but
  they have no radial structure at all — no spokes, no hub, no rings. An arc is
  not a web. The user's words: *"you just made curved arcs"*.
- **The corner webs inside the panel are effectively gone.** They were
  constrained to `maxWidth: 20%` / `maxHeight: 44%` with opacity dropped to
  0.28–0.44 and stroke opacity to 0.7–0.75. On the real panel that leaves faint
  slivers in two corners. The user's words: *"you did not add anything in the
  corners"* and *"you ruined the webs inside box"*.

### What the good version looked like, so it can be rebuilt

The version the user approved (before the last pass) had corner webs that:

- anchored a hub *inside* each corner and ran spokes out to anchors placed at
  **evenly spaced fractions along both adjacent edges** — this is what made the
  strands visibly terminate on the panel border;
- were sized in **absolute pixels, 88–250px**, with **no `maxWidth`/`maxHeight`
  caps and no `preserveAspectRatio`** — the caps are what shrank them into
  invisibility, because a square viewBox inside a non-square cap letterboxes;
- used opacity **0.30–0.46** with spoke stroke at full weight;
- placed **seven** webs: one per corner plus extras offset along an edge at the
  top-right, bottom-left and bottom-right, so per-corner counts were uneven.

The current file replaced that even-fraction anchoring with random-angle ray
casting. The ray-casting idea is sound and does produce genuinely different webs
per seed — **keep it** — but it was shipped together with the size caps and the
opacity reduction, and those are what destroyed the result.

### Recovery is not possible from git

`components/spiderverse/SpiderWeb.tsx` **has never been committed** — it shows as
`??` in `git status`. The approved version exists only in the previous session's
transcript. Rebuilding from the notes above is the realistic path.

**Commit the file before doing anything else**, so the next iteration is
revertible. Several UI files in this repo are in the same untracked state.

## 3. Known issues and things to watch

- **`npm run dev` and `npm run build` share `.next` and corrupt each other.**
  Switching between them without `rm -rf .next` produces
  `TypeError: __webpack_modules__[moduleId] is not a function` and a 500, and
  occasionally a `WasmHash` crash during build. Always clear `.next` when
  switching. This has cost real debugging time twice.
- **The QA suite lives in the session scratchpad and evaporates.** It has been
  rebuilt from scratch twice already. It is three dependency-free files —
  `cdp.mjs` (a Chrome DevTools Protocol driver using Node's built-in WebSocket),
  `fixture.mjs` (self-resetting seed data), and the suites. Playwright MCP does
  not work here: it wants a Chrome channel at `/opt/google/chrome` that is not
  installed, so the driver talks to the Playwright-bundled Chromium at
  `~/.cache/ms-playwright/chromium-1234/chrome-linux64/chrome` directly.
  **Move it into the repo** (e.g. `qa/`, excluded from tsconfig and eslint) so
  this stops repeating.
- **Never point a dev server at `prisma/dev.db` for testing.** Copy it to a
  scratch path and set `DATABASE_URL` to the copy. The real database is the
  user's own data.
- **The Next.js dev-tools badge** (the circled "N", bottom-left) is not an app
  component and cannot be styled. It only appears under `npm run dev`.
  `devIndicators: false` in `next.config.ts` removes it if asked.

## 4. Decisions made recently that are already in DECISIONS.md or CLAUDE.md

Nothing from the last pass is missing from the docs. For the record, the two
that most often get "corrected" back by a later session, both recorded in
`CLAUDE.md`:

- **Typography is one family.** Bangers carries the entire interface — headings,
  labels, body, buttons and numerals. This reverses an earlier rule that
  reserved it for the wordmark. The user asked for it explicitly. Known cost:
  Bangers has strongly proportional figures (38% width spread across 0–9), so
  counters shift slightly as values change.
- **Yellow is both the streak colour and the primary CTA fill.** The user was
  told this weakens the streak signal and chose it anyway. Magenta remains
  volume and active state, not the button fill.
- **Radius is 0 everywhere**, controls included.
