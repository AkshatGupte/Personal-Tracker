## 2. What exists today

**Data model** — `Track → Topic → Task → CompletionLog`. No schema change is
needed for anything in Phase 2.

**The completion engine** (Item 6, the load-bearing part of the app):

- `Task.status` + `Task.completedAt` own current task state; the completion
  ratio is derived from them on read, never stored.
- `CompletionLog` owns daily history — one row per track per day, `date`
  normalised to **local** midnight.
- Today's row is a **recomputed rollup** of tasks completed today. Earlier days
  are frozen and never rewritten. Recompute, never increment — that is what
  makes double-clicks, retries and complete→uncomplete→complete idempotent.
- Strict streaks: a missed day resets to 0. No freezes, no grace. Today does
  not count as missed until it is over.
- The displayed streak is **recomputed from `CompletionLog` on read**, because
  inactivity writes nothing and so no write path could ever catch a lapse.
- All writes go through one transaction in `lib/completion.ts`.

**Routes** — `/` (home), `/tracks/[id]`, `/progress` (weekly summary).

**Library layer** — `lib/day.ts` (the single source of day boundaries, local
time), `lib/streak.ts`, `lib/completion.ts`, `lib/terrain.ts`, `lib/rollup.ts`
(period-generic), `lib/progress.ts` (reads), `lib/motif.ts`, `lib/web.ts`.

**Components** — `Panel`, `TopNav`, `TerrainProfile`, `ProgressRing`,
`StreakHeatmap`, `WeekStrip`, `TrackRow`, `TopicRow`, `TaskRow`,
`InlineCreateForm`, `NewTaskForm`, `AtmosphereField`, `LatticeWeb`.

## 4. The UI system

### One theme, four atmospheres

**There is no light/dark toggle.** It was removed. One palette: black ground,
purple accent. The day's atmosphere is the only variation the interface
carries. Holding a second palette meant every motif was capped by whichever
theme had less contrast headroom — always the light one.

The day's motif is stamped on `<html>` as `data-motif`, resolved on the server
by `lib/motif.ts`.

| Motif | Idea | Signature | Palette |
|---|---|---|---|
| `voyage` | voyage, cartography | rhumb lines radiating from one bearing | indigo `rgb(60 105 175)` |
| `lattice` | tension, multiverse | **drawn SVG** hex lattice + chromatic split | neon magenta `rgb(236 40 140)` → blue `rgb(40 90 235)`, white edges |
| `beacon` | one light source | concentric rings, luminous core | cyan `rgb(20 190 215)` |
| `terrace` | weekend, pitch | mown vertical banding, no square grid | pale sky `rgb(120 180 230)` |

**Rotation** — weekends are always `terrace`. Weekdays cycle, counted **Monday
to Monday** (`lib/motif.ts` counts from a fixed Monday; using the Unix epoch was
a bug — 1 Jan 1970 is a Thursday, so the index rolled over mid-week). Result:
Monday pairs with Thursday, Tuesday with Friday, Wednesday stands alone, and
all three appear in every week. Which motif lands on which day shifts weekly.

```
Tue 01 Sep → beacon      Sat 05 Sep → terrace
Wed 02 Sep → voyage      Mon 07 Sep → beacon
Thu 03 Sep → lattice     Wed 09 Sep → lattice
```

To see a specific motif without waiting for its day, override `data-motif` on
`<html>` in the browser — but note **`lattice` also gates a server-rendered
component** (`LatticeWeb`), so a client-side override will not summon its web.
For that, force it server-side.

### The rules that must not be broken

1. **A motif may never colour data.** `accent` (progress/terrain), `streak`
   (consistency/ember), `positive` (completion) keep their meanings on every
   day. This is asserted in the checks — do not weaken it.
2. **The motif is never named in the interface.** No labels, tooltips or
   captions. If it has to be explained, it has failed.
3. **Abstract only.** No characters, logos, crests, wordmarks, slogans or
   licensed artwork — ever, including in personal builds. Geometry, light and
   hue.
4. A motif *may* decorate **non-data** elements (a display heading, a section
   marker), scoped by `[data-motif="x"]`. This is newer than CLAUDE.md's
   original "ground only" rule and is deliberate.

### The lattice is the exception

Every other motif is CSS gradients on `.atmosphere`. `lattice` additionally
draws real SVG (`components/LatticeWeb.tsx`, geometry from `lib/web.ts`)
because a gradient can only make a *field* — a lattice needs edges with ends,
gaps and broken cells. It also carries a chromatic split (drawn three times at
sub-pixel offsets: cyan low, magenta high, true colour on top) and applies the
same misregistration to display headings, plus a 🕸 marker on section labels.

**Uncommitted.** The last session reworked lattice from a red/blue spider web
to this neon multiverse form against a Spider-Verse-styled reference. It is
built and verified but not committed, and the user had not yet seen it live on
a lattice day (next is Thu 3 Sep). Two things they flagged to look at: the
emoji marker cuts against the mono-label editorial system, and it renders
monochrome in headless screenshots so its real appearance is unverified.

## 5. UI procedure — generate, verify against a reference, iterate

This is the loop that worked. Follow it rather than eyeballing once and
declaring done.

### Setup, once per session

The scratchpad is wiped between sessions, so the helpers must be recreated.

- **Playwright MCP does not start here** (pinned to the `chrome` channel; only
  chromium is installed). Use the module directly:
  `/home/rendred/.npm/_npx/705bc6b22212b352/node_modules/playwright`
  (v1.62.1 — matches the installed chromium-1234). The other npx cache wants
  revision 1237 and fails.
- **Never kill node processes broadly and never `rm -rf .next` blindly.** The
  user runs their own dev server. Doing this mid-session deleted their build
  out from under them and produced a runtime
  `__webpack_modules__[moduleId] is not a function`. Scope kills to your own
  PIDs, and prefer a dedicated high port (4000+).
- Verify against a **production build** (`npm run build && next start`), not
  dev — it is stricter and matches what ships.

### The loop

**Step 1 — Read the reference honestly.** Separate three things before
building: what is *aesthetic* (transferable), what is *structure* belonging to
a different product (not transferable — Rendred is Track → Topic → Task), and
what is *licensed artwork* (never transferable). Say which is which before
writing code; a reference is rarely all one thing.

**Step 2 — Seed a realistic fixture.** An empty database makes every screen
look broken and every critique measure an empty room. Create a track with
topics, ~8 tasks with some completed, and `CompletionLog` rows spread across
the 12-week window — including gaps and empty weeks. Name fixtures
distinctively (`QA …`) so cleanup can target them by name.

**Step 3 — Build, serve, screenshot.** 1440×900 and 390×844 minimum.

**Step 4 — Actually look at the screenshot.** Read it as an image. This is the
step that catches what assertions cannot: a slab where a strip was intended, a
caption floating unattached, a week that reads as broken because six of seven
cells are hidden.

**Step 5 — Measure. Three checks, all scriptable:**

- **Motif presence** — screenshot with the motif on, then with
  `data-motif="none"`, and diff the pixels in a canvas. Report mean delta and
  the share of pixels changed by ≥5. Benchmarks on the track page, dark:
  `voyage 5.91 / 39.7%`, `beacon 6.43 / 26.8%`, `terrace 13.10 / 78%`. A motif
  well below that band is invisible; well above it competes.
- **Composited-ground contrast** — hide page content, screenshot, find the
  worst ground pixel inside the reading column (x 208–1232 at 1440 wide), and
  compute its contrast against `--muted`. **Hide with `display:none`, not
  `visibility:hidden`** — heatmap and week-strip cells set inline
  `visibility: visible` and will override a hidden parent, poisoning the
  measurement. Benchmarks: no motif `6.04:1`; `voyage 4.51`, `terrace 4.92`,
  `lattice 4.73`. The floor is `4.5:1`. Every motif sits just above it, so this
  is the binding constraint on how vivid anything can be.
- **Semantic isolation** — read the computed ridge stroke, completion-tick
  colour and the three semantic tokens under each of the four motifs and assert
  they are identical. This is the rule that protects the product.

**Step 6 — Compare to the reference and name the deltas** as a list, largest
first. "It doesn't match" is not actionable; "the web reads as diagonal streaks
because the hub is off-canvas" is.

**Step 7 — Fix the largest delta and return to step 3.** Expect three to five
rounds. Real examples from the last session: the atmosphere was calibrated in
215px specimen frames and had to be halved once it was on a full page; the
lattice mask took four passes (`0.25 → 3.28:1`, `0.20 → 4.36:1`, `0.15 →
4.73:1`) to clear the contrast floor.

**Step 8 — Stop when** the remaining differences are stylistic preference
rather than structural mismatch, and all three measurements pass. Then run the
full check set (below), delete the fixtures, and report the numbers rather than
claiming it looks right.

### Full check set before calling a UI change done

`npx tsc --noEmit` · `npx eslint` · `npm run build` · contrast on every motif ·
semantic isolation · reduced motion (`document.getAnimations()` filtered to
`running` must be 0) · no sideways scroll at 390/768/1440 on all three routes ·
keyboard reach and a visible focus ring on any new control · browser console
clean · database integrity · **fixtures removed**.

### Traps that cost time

- **`--m-*` tokens are scoped to `.atmosphere`.** A treatment outside that
  layer must read the `--lattice-*` / `--voyage-*` palettes on `:root`. An
  unresolved custom property makes the *entire declaration* invalid at
  computed-value time — it fails silently. Assert on computed style, not on a
  screenshot, or you will not catch it.
- **Per-stroke alpha compounds at crossings.** Overlapping translucent strokes
  brighten at every join and blew the contrast floor. Draw at full alpha and
  fade the flattened element with `opacity` instead.
- **Full-bleed offsets must be measured from the container**, not `50%` — a
  percentage resolves against whichever column the element sits in.
- **Masks keyed to `--gutter`** (`max(0px, calc((100vw - 64rem) / 2))`) degrade
  correctly: below the container width there is no margin, so the effect falls
  back to its safe strength instead of putting full weight over text.
- **Emoji renders monochrome in headless chromium** (no colour emoji font).
  Its real appearance cannot be verified from a screenshot here.
- A `"use server"` module may only export async functions — constants belong in
  a plain module.
- A Tailwind `@theme` token containing `var()` must go in `@theme inline`, or
  every utility built from it silently dies.
- `outline-none` defeats the global focus ring. Never add it.
- Grid children need an explicit `grid-cols-1` at the base, or they push past
  the viewport on phones.
- A stale `.next` can produce a webpack `WasmHash` crash at build time with no
  reference to any project file. `rm -rf .next` and rebuild before hunting a
  phantom code bug.

## 6. Known issues

- **`npm audit`**: 4 high, 1 moderate, all PostCSS advisories via Next 15's
  bundled copy. The only fix is Next 16, a breaking upgrade. Left alone
  deliberately.
- **Prisma is pinned exactly** at 7.10.0 for both `prisma` and
  `@prisma/client`. `npm install prisma@latest` resolves to an 8.x prerelease
  against a 7.x client and silently mismatches. Do not run `npm update` on
  these.
- **Skills are not reliably offered.** `playwright-visual-qa`,
  `prisma-conventions`, `streak-logic` and `llm-call-conventions` live in
  `.claude/skills/`. If one you need is missing from the session list, read its
  `SKILL.md` from disk and follow it manually.
- `buildTerrain` does not enforce monotonicity — it is a plain cumulative sum.
  Terrain only rises because the write policy never rewrites past days, not
  because the maths prevents it.
