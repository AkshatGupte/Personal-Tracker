## The immediate next step

**Item 6: mark a task complete.** The completion model was settled and approved
on 2026-08-30, before any code was written. Do not re-litigate it; the full
entry is at the top of `docs/DECISIONS.md`. The short version:

- `Task.status` and `Task.completedAt` own individual task state
- The completion ratio is derived from `Task.status` on read, never stored
- `CompletionLog` owns historical daily activity: streaks, heatmap, terrain
- `Track.currentStreak` / `longestStreak` / `lastActivityDate` are a cache that
  can always be rebuilt from `CompletionLog`

**Today's `CompletionLog` row is a recomputed rollup of `Task.completedAt`, and
earlier days are frozen.** On completion or uncompletion: set or clear the task
fields, then recompute only the current day's row. Never rewrite an earlier day.

**Recompute, never increment.** `increment: 1` double-counts on complete,
uncomplete, complete. Recomputing is idempotent, which also makes double-clicks
and retries safe. Recompute the streak from `CompletionLog` rather than doing
`currentStreak + 1`.

Three things to get right, each explained in `docs/DECISIONS.md`:

1. **Normalise `CompletionLog.date` on every write.** The unique constraint
   compares the full `DateTime`, so `new Date()` creates a new row per
   completion instead of upserting. Reads would hide the damage.
2. **Move day boundaries to local time** through one shared `startOfDay()`
   helper used by both reads and writes. Everything is UTC today, which rolls
   the day at 05:30 IST and can break a strict streak unfairly.
3. **Reset the streak on read.** Nothing resets `currentStreak` anywhere today,
   and `lastActivityDate` is never written. An inactive user triggers no
   writes, so the reset has to happen when the value is read, which is what the
   `streak-logic` skill requires.

Write all three in one transaction: task fields, the day's log row, and the
track's cached streak scalars.

Item 6 is also what finally brings the terrain to life. Nothing writes
`CompletionLog` today, so elevation is zero and the heatmap is empty for every
real user until this lands. Verify the zero-to-one transition renders.

Load the `streak-logic` skill before writing streak code (see the skills
warning below).

## Known issues and things to watch

**A `"use server"` module may only export async functions.** A constant array
exported from `lib/actions/tasks.ts` crossed the server/client boundary as a
non-array and crashed the track page with "DIFFICULTIES.map is not a function".
Constants now live in `lib/difficulty.ts`. Item 6 will want streak constants:
put them in a plain module. Type-only exports from an action module are fine,
because they are erased at compile time.

**Tailwind: a `@theme` token containing `var()` must go in `@theme inline`.**
Getting this wrong silently kills every utility built from it, with no error
anywhere. It once disabled all three fonts at once.

**`outline-none` defeats the global focus ring.** Focus rings are declared once
in the base layer of `app/globals.css`. Do not add `outline-none` to any
control.

**Grid children need an explicit base column.** Both pages use
`grid grid-cols-1 ... lg:grid-cols-[...]`. Without `grid-cols-1`, grid items
default to `min-width: auto` and push the page wider than the viewport on
phones.

**`buildTerrain` does not enforce monotonicity.** It is a plain cumulative sum
and would render a decrease faithfully. Terrain only rises because the write
policy never rewrites past days, not because the maths prevents it.

**Plus Jakarta Sans has a very narrow space glyph.** `body` carries
`word-spacing: 0.06em` to compensate. Removing it makes words run together.

**Skills are not reliably offered.** `playwright-visual-qa`, `prisma-conventions`,
`streak-logic` and `llm-call-conventions` exist in `.claude/skills/` but have
not always appeared in the session's available-skills list. If a skill you need
is missing, read its `SKILL.md` from disk and follow it manually.

**The Playwright MCP server does not start here.** It is pinned to the `chrome`
channel and only Chromium is installed. Visual QA has been run with a short
Playwright script from the scratchpad instead, which adds no project
dependency. Adding `--browser chromium` to the server args in `~/.claude.json`
would fix the MCP path.

**`npm audit` reports 4 high and 1 moderate.** All are PostCSS advisories
reaching us through Next 15's bundled copy. The only fix is Next 16, a breaking
upgrade. Left alone deliberately.

**Prisma versions are pinned exactly.** `prisma` and `@prisma/client` are both
7.10.0. `npm install prisma@latest` resolves to an 8.x prerelease while the
client resolves to 7.x, which silently mismatches. Do not run `npm update` on
these.

## Design direction, in one paragraph

CLAUDE.md is the source of truth and has been rewritten twice; trust the file,
not older entries in `docs/DECISIONS.md`, which record superseded directions.
Current direction: dark black and purple as primary, light blue and white as
the second theme, one semantic token set, Plus Jakarta Sans. The distinctive
element is the terrain: elevation is cumulative completed tasks, contour strata
sit at fixed heights so a steep climb visibly bunches them, and milestones are
drawn only where they were actually crossed. Never fabricate progress. Three
signals stay separate: volume (terrain, accent), consistency (streak and
heatmap, ember), completion (`positive`, still unused until item 6).
