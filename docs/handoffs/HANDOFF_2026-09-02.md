## 2. The check-in model — read this before touching completion code

**Tasks are persistent recurring activities, checked in once per day.** A task is
never permanently completed. `Task.status` and `Task.completedAt` are **gone**.

- `TaskCheckIn { id, taskId, date, createdAt }` with `@@unique([taskId, date])`
  is the ground truth. The row's existence *is* the state; undo deletes it.
- `CompletionLog` is unchanged in shape and remains a derived per-track daily
  rollup — only what it is computed *from* changed.
- **`CompletionLog` is a rollup, never frozen history.** Deleting a task or topic
  cascades its check-ins and then rebuilds *every day it touched*, not just
  today. Affected dates are collected **before** the delete, because the cascade
  destroys the evidence. `recomputeDays` and `affectedDays` in `lib/completion.ts`.
- A consequence the user accepted explicitly: **a streak can shorten if you
  delete the work that earned it.**
- Untouched, and verified rather than assumed: `lib/streak.ts`, `lib/terrain.ts`,
  `lib/rollup.ts`, the heatmap and the weekly summary. They count active days and
  are indifferent to recurrence.

Verified with 26 engine assertions and 9 UI assertions, all passing. Migration
`20260901164753_recurring_task_check_ins` is applied and includes a backfill,
tested against a seeded copy with a deliberate edge case (a task completed at
00:30 IST — the previous day in UTC — which filed under the correct local day).

## 3. The trap that will bite you

**Any `prisma generate` requires a full dev-server restart.** `lib/prisma.ts`
caches the client on `globalThis` so HMR does not exhaust connections. That is a
good decision, but it means a regenerated client is *never* picked up by a
running dev server — the old instance is pinned in memory. The symptom is
`Cannot read properties of undefined (reading 'count')` on a new model.

This already happened once this session. If it recurs:

```
# Ctrl-C the dev server, then
npm run dev
# and if it persists, the .next cache is the second stale copy:
rm -rf .next && npm run dev
```

**Never kill the user's dev server yourself** — doing so in an earlier session
destroyed their build mid-work. Tell them and let them do it.
